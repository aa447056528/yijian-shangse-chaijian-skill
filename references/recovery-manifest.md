# 范围、记录与恢复

开始模型测试或交付、恢复中断工作、整理最终导出时读。本约定不要求只读技能评审创建模型项目。复制 [manifest示例](../assets/manifest.example.json) 后填写实际内容；示例的空哈希和NOT_RUN状态不能作为通过证据。

## 最小记录

项目的 `manifest.json` 使用以下字段，文件路径相对该清单所在目录；`exports[].file` 例外，相对传给回读脚本的STL目录，且只能是根目录文件名。

| 字段 | 用途 |
|---|---|
| `schema_version`、`skill_version` | 记录格式和技能版本 |
| `scope` | `mode` 为 `method_validation` 或 `model_delivery`；列目标件、必要邻件和不在本轮范围的区域 |
| `units`、`tools` | 毫米约定、源到毫米的比例、工具实际版本；未知值保留null，涉及毫米的设计前补齐 |
| `fabrication` | 工艺、装配总高和各参数来源；未指定时FDM、200 mm，来源为`skill_default`；喷嘴等未知项保留null |
| `stage` | 当前仍有有效证据支持的最近阶段，初始为DRAFT |
| `artifacts` | 每个产物的唯一 `id`、`path`、内容 `sha256`、`depends_on`；来源映射和接口定义作为可恢复产物保存 |
| `required_checks`、`checks` | 本轮所需检查ID，以及其状态、绑定的产物哈希、证据路径、范围和失效原因 |
| `exports` | 预期交付STL的 `file`、`part_id`；需要锁定已有导出版本时可加 `sha256` |

局部复用需要相应记录粒度：将需要独立核验的部件、共享边界或参数保存为独立产物文件并分别记录哈希与依赖。例如眼窝边界只使实际依赖它的接口与检查失效，头发是否可复用由其独立产物和依赖证明。若只有一个整模文件且无法可靠核验未变区域，就保守扩大重检范围，不能把新哈希填进旧检查冒充已验证。

同一物理件可对应多个分色文件，因此文件名必须唯一，`part_id`不必唯一。颜色、装配/打印变换及接口参数可作为清单扩展字段或独立产物，不把网格数组塞进清单。

参数来源区分`user`（本轮明确指定）、`confirmed_project`（本项目此前确认）与`skill_default`。恢复时不以模板默认值覆盖现有项目；更改高度或工艺按依赖使相应检查失效。在参数产物中记录竖直方向、装配高度的包含范围、缩放前后高度与等比倍率；总高200 mm不等于喷嘴、材料或装配间隙已知。示例中的`parameters`文件需实际创建、计算哈希，并与`fabrication`和`units`保持一致。

候选网格与获批网格明确区分。切面/重排后记录新面来源映射及标签所绑定的网格版本；NPZ等单文件同时保存网格、标签和映射时写明键名及各自索引域。新候选的渲染、检查与可编辑文件须使用同一版本；旧几何PASS不能移作新候选或整件语义PASS。

`checks[].inputs` 保存执行检查时的 `artifact_id → sha256` 快照。每个必要检查必须有明确范围和证据，不能只登记一个总PASS。样例只示范记录形状；按实际任务补齐所需检查，删除不适用项并在 `scope` 说明理由。

## 阶段出口

| 阶段 | 必须仍有效的证据 |
|---|---|
| WORKING_READY | 范围内的修形/保留依据、外观与基础几何检查 |
| REGIONS_READY | 标签结构和部位语义；范围内待实体化的表面无未解决UNKNOWN |
| SURFACES_APPROVED | 获批外表面、共享边界和来源映射 |
| INTERFACES_PLANNED | 成对接口定义、归属、尺寸、邻接及装入顺序 |
| SOLIDS_CHECKED | 本轮必要的外观、拓扑、自交、厚度、配合、装入路径与落床检查 |
| EXPORTED | 实际文件已生成且回读；数量、尺度、对齐与清单一致 |

方法验证只覆盖声明的目标及必要邻件，可以在达到测试目标的阶段结束。EXPORTED仅表示导出阶段完成，不覆盖其他检查状态。必要项为FAIL、NOT_RUN或证据过期时不能声称完整验收通过；WARN须说明局限及是否影响本次通过条件。`BLOCKED_CAPABILITY`记录为阻塞原因，未能执行的检查仍为NOT_RUN。

## 恢复与局部失效

1. 读取scope和产物清单，核对输入及将复用产物的实际SHA-256；文件缺失、哈希为空或不一致均不能直接复用其通过状态。
2. 沿 `depends_on` 找到受影响的下游产物和检查。比较检查的 `inputs` 快照与当前哈希；保存旧证据，但将过期检查设为NOT_RUN，并在 `invalidated_by` 记录变化产物与原因。
3. 将stage退回仍满足出口条件的最近阶段，只重做失效范围。边界变更至少影响相邻双方接口和配合；装配顺序变更影响相关路径检查。依赖不仅包括网格，也包括参数、单位和工具配置。
4. 最终验收核对 `required_checks` 中每一项均存在且证据对应当前版本，再核对预期导出清单。未变化且证据完整的检查可以复用。

网格未变但新视图或用户反馈证实原验收错误时，原语义/接缝检查改为FAIL并记录失败位置和证据；不能因哈希相同保留PASS。依赖该归属的接口、实体与导出验收标为NOT_RUN并注明上游失败，阶段退回仍有效的出口。保留旧文件用于排查，同时明确标记为不可交付。修正后的候选在重新检查前仍为NOT_RUN；不能以“已补种子”或“已改切面”宣布问题修好。

这里是执行约定，包内没有自动维护整个依赖图的程序。`check_stl_exports.py --manifest` 只核对 `exports` 与实际STL文件及基础几何，不验证本表全部阶段，也不自动判定语义、美术或装配通过。
